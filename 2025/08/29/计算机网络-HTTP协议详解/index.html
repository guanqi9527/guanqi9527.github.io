计算机网络-HTTP协议详解

一、什么是HTTP协议？

HTTP（Hypertext Transfer Protocol，超文本传输协议）是一种用于传输超媒体文档（如HTML）的应用层协议。它是互联网中最常用的协议之一，基于客户端-服务器模型，通过请求-响应的方式进行通信。

1.1 HTTP的核心特点

  • 无连接：每次请求-响应后，连接会被关闭（HTTP/1.0）或重用（HTTP/1.1及以上）
  • 无状态：服务器不会保存客户端的状态信息
  • 媒体独立：可以传输任意类型的数据，只要客户端和服务器知道如何处理
  • 简单快速：协议简单，通信速度快

1.2 HTTP的发展历程

  • HTTP/0.9：1991年，仅支持GET方法，无首部字段
  • HTTP/1.0：1996年，增加POST和HEAD方法，引入首部字段
  • HTTP/1.1：1999年，增加持久连接、管道化传输、分块传输编码等
  • HTTP/2.0：2015年，引入二进制分帧、多路复用、服务器推送等
  • HTTP/3.0：2022年，基于QUIC协议，进一步提高性能

二、HTTP请求和响应

HTTP通信由请求和响应组成，分别由客户端和服务器发送。

2.2 HTTP响应格式

2.3 请求方法

HTTP定义了多种请求方法，用于表示对资源的操作：

  • GET：获取资源
  • POST：提交资源（创建或更新）
  • PUT：更新资源
  • DELETE：删除资源
  • HEAD：获取资源的首部信息
  • OPTIONS：获取资源支持的请求方法
  • PATCH：部分更新资源
  • CONNECT：建立隧道连接
  • TRACE：追踪请求路径

2.4 状态码

状态码用于表示请求的处理结果，分为5类：

  • 1xx（信息性状态码）：请求已接收，继续处理
  • 2xx（成功状态码）：请求已成功处理
    • 200 OK：请求成功
    • 201 Created：资源创建成功
    • 204 No Content：请求成功，但无响应体
  • 3xx（重定向状态码）：需要进一步操作
    • 301 Moved Permanently：永久重定向
    • 302 Found：临时重定向
    • 304 Not Modified：资源未修改
  • 4xx（客户端错误状态码）：请求有错误
    • 400 Bad Request：请求语法错误
    • 401 Unauthorized：未授权
    • 403 Forbidden：禁止访问
    • 404 Not Found：资源不存在
  • 5xx（服务器错误状态码）：服务器处理请求出错
    • 500 Internal Server Error：服务器内部错误
    • 502 Bad Gateway：网关错误
    • 503 Service Unavailable：服务不可用
    • 504 Gateway Timeout：网关超时

三、HTTP首部字段

HTTP首部字段用于传递额外的信息，分为以下几类：

3.1 通用首部字段

  • Cache-Control：控制缓存行为
  • Connection：控制连接行为
  • Date：消息发送的日期和时间
  • Pragma：控制缓存（HTTP/1.0）
  • Trailer：说明消息尾部的字段
  • Transfer-Encoding：传输编码方式
  • Upgrade：协商升级协议
  • Via：记录请求经过的代理服务器

3.2 请求首部字段

  • Accept：客户端可接受的媒体类型
  • Accept-Charset：客户端可接受的字符集
  • Accept-Encoding：客户端可接受的编码方式
  • Accept-Language：客户端可接受的语言
  • Authorization：身份认证信息
  • Cookie：客户端的Cookie信息
  • Host：目标主机名和端口号
  • If-Match：条件请求（比较ETag）
  • If-Modified-Since：条件请求（比较最后修改时间）
  • If-None-Match：条件请求（比较ETag）
  • If-Unmodified-Since：条件请求（比较最后修改时间）
  • Origin：请求的源站
  • Proxy-Authorization：代理服务器认证信息
  • Range：请求资源的部分内容
  • Referer：请求的来源页面
  • User-Agent：客户端信息

3.3 响应首部字段

  • Access-Control-Allow-Origin：允许的跨域请求源
  • Age：资源在缓存中的年龄
  • ETag：资源的实体标签
  • Location：重定向的目标URL
  • Proxy-Authenticate：代理服务器认证要求
  • Server：服务器信息
  • Set-Cookie：设置Cookie
  • Vary：指定缓存的判断标准
  • WWW-Authenticate：身份认证要求

3.4 实体首部字段

  • Content-Encoding：内容编码方式
  • Content-Language：内容语言
  • Content-Length：内容长度
  • Content-Location：资源的实际位置
  • Content-Range：部分内容的范围
  • Content-Type：内容类型
  • Expires：资源的过期时间
  • Last-Modified：资源的最后修改时间

四、HTTP缓存

HTTP缓存是提高Web性能的重要手段，分为强制缓存和协商缓存。

4.1 强制缓存

  • Expires：HTTP/1.0，指定资源的过期时间
  • Cache-Control：HTTP/1.1，优先级高于Expires
    • max-age：资源的最大缓存时间（秒）
    • public：可以被任何缓存缓存
    • private：只能被客户端缓存
    • no-cache：不使用强制缓存，需要协商缓存
    • no-store：不缓存任何内容

4.2 协商缓存

  • Last-Modified/If-Modified-Since：基于最后修改时间
  • ETag/If-None-Match：基于实体标签（优先级更高）

4.3 缓存流程

  1. 客户端第一次请求资源，服务器返回资源和缓存信息
  2. 客户端第二次请求资源，先检查强制缓存
    a. 如果资源未过期，直接使用缓存
    b. 如果资源已过期，进行协商缓存
  3. 协商缓存时，客户端发送资源的标识（Last-Modified或ETag）
  4. 服务器判断资源是否变化
    a. 如果未变化，返回304 Not Modified
    b. 如果已变化，返回新资源和新的缓存信息

五、HTTP/2.0新特性

HTTP/2.0相比HTTP/1.1有以下主要改进：

5.1 二进制分帧

  • 将请求和响应拆分为二进制帧进行传输
  • 提高传输效率和解析速度

5.2 多路复用

  • 多个请求和响应可以在同一个TCP连接上并发传输
  • 避免HTTP/1.1中的队头阻塞问题

5.3 服务器推送

  • 服务器可以主动向客户端推送资源
  • 减少请求次数，提高性能

5.4 头部压缩

  • 对HTTP首部进行压缩，减少传输量

5.5 优先级

  • 可以为请求设置优先级，服务器根据优先级处理请求

六、HTTPS

HTTPS（HTTP Secure）是HTTP的安全版本，通过SSL/TLS协议加密通信内容。

6.1 HTTPS的工作原理

  1. 客户端与服务器建立TCP连接
  2. 客户端发送SSL/TLS握手请求
  3. 服务器返回SSL/TLS证书
  4. 客户端验证证书
  5. 客户端和服务器协商加密算法和会话密钥
  6. 客户端和服务器使用会话密钥加密通信内容

6.2 HTTPS的优势

  • 保密性：通信内容被加密，防止窃听
  • 完整性：防止数据被篡改
  • 认证：验证服务器身份，防止中间人攻击
